# Airflow VM runtime bundle

This package defines the Airflow 3.4 VM runtime; it does not create a VM or call Google Cloud from CI. The image is built from the reviewed Airflow base digest and copies the production Mini3 DAGs into /opt/airflow/dags. At VM boot, startup.sh requires the approved Artifact Registry repository and a sha256 image digest, uses the attached VM identity for a short-lived registry token stored only under /run, pulls the image, and copies its non-secret runtime files to the host.

The systemd unit starts bootstrap.py. It verifies the project and attached service account using the Compute Engine metadata server, fetches the three authorized Secret Manager values in memory, and writes them only to root-owned files under the host /run tmpfs. Compose bind-mounts each value read-only only into the container that needs it. Airflow uses the documented _CMD configuration interface, PostgreSQL uses its password-file interface, and no plaintext secret is placed in a container environment or command argument. The admin is created through the FAB security manager; the password is hashed before the metadata database commit and never logged. Teardown removes the containers before deleting the tmpfs files. No ADC file is mounted.

The weather cloud gate defaults to false and can only read an explicit dataforge-weather-cloud-enabled VM metadata attribute. The Airflow DAG is paused on creation. Compose publishes port 8080 on the VM interface; the C4 firewall must remain limited to IAP TCP forwarding. Every service uses the Docker gcplogs driver and supplies container_name, application, and phase labels for the C3 log filters.

Systemd is the single restart supervisor. Bootstrap starts PostgreSQL, waits for its healthcheck, runs the one-shot migration/pool/FAB initialization, then keeps Compose attached to the four Airflow services. An unexpected container exit ends the Compose process; systemd restarts the full stack after failure. Compose does not set its own restart policy.

The local CI job builds and smoke-tests the image, checks the Compose model with disposable placeholders, runs bootstrap unit tests, and syntax-checks startup.sh. The FAB smoke test mounts its test-only password under container tmpfs and confirms that only a hash remains in the metadata database. CI does not publish the image. Before any VM apply, an authorized CI path must publish the image to the existing private Artifact Registry repository and record its immutable digest. The VM service account must already be able to pull that repository; this runtime package does not grant IAM roles. The current R1 snapshot did not show roles/artifactregistry.reader on the VM identity, so verify effective repository permissions before attempting C4.

The host bootstrap installs Debian docker.io and docker-compose packages at VM startup. Secret Manager access, Artifact Registry reads, Docker logging, systemd startup, health checks, and IAP access require live verification after the separately authorized Phase 4 gates. No live deployment is claimed here.
