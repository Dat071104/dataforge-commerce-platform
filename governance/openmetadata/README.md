# W9 OpenMetadata CI profile

This profile runs only through `.github/workflows/week9-catalog.yml`. Do not start Docker or OpenMetadata locally.

The workflow parses dbt with the credential-free `offline` profile, starts an ephemeral OpenMetadata 2.0.7 server with PostgreSQL 16 and OpenSearch 2.19, registers the `dataforge_w9_catalog` service, then invokes the version-matched OpenMetadata CLI against the CI `manifest.json`. It next attempts BigQuery metadata ingestion through the `dataforge-w9-meta-read` WIF identity supplied by repository variables `W9_WIF_PROVIDER` and `W9_META_READ_SA_EMAIL`. The stack has no Airflow service, and no service-account key is stored. dbt artifact ingestion is separate from live BigQuery catalog evidence and G7 execution lineage.

The connector first lists project dataset IDs, then applies the `schemaFilterPattern` before it lists table metadata ([source, dataset enumeration and filter](https://github.com/open-metadata/OpenMetadata/blob/2.0.7-release/ingestion/src/metadata/ingestion/source/database/bigquery/metadata.py#L654-L681), [post-filter dataset path](https://github.com/open-metadata/OpenMetadata/blob/2.0.7-release/ingestion/src/metadata/ingestion/source/database/bigquery/metadata.py#L817-L840)). The dataset-ID listing is metadata-only and is within AF2's project-scoped `roles/bigquery.metadataViewer` grant. The exact allowlist is `w9_drill`, `dataforge_dq`, `restricted_pii`, `pii_safe`, and `dbt_ci_pr_*`; table metadata ingestion is restricted to those datasets. No W7 table metadata is queried or included in evidence. The connector configuration disables profiler/sample data, usage/query logs, policy tags, DDL, owners, and stored procedures; it does not request table rows or modify source resources.

OpenMetadata's documented connector permissions include `bigquery.tables.getData`, `bigquery.jobs.create`, and `bigquery.jobs.listAll` for metadata ingestion, beyond AF2's metadata viewer and Data Catalog viewer grants. No IAM is expanded. The workflow suppresses raw connector logs and writes only a recognized permission name or a generic failure category to the Actions summary. A permission denial is recorded as `DATAPLEX_FALLBACK_REASON`; BigQuery ingestion remains **UNVERIFIED** until the Actions run. Dataplex is the designated live GCP lineage path, pending G7's integrator-run dbt build and captured lineage event.

WIF review item (resolved 2026-11-21, AF2-ext-2c): the `github-oidc` provider now trusts only `pull_request_target`, `push`, `workflow_dispatch` and `schedule` events. This job's `pull_request` trigger therefore cannot obtain a WIF token; the `continue-on-error` auth step falls back to the Dataplex path. Live BigQuery metadata ingestion runs only through a `workflow_dispatch` of this workflow on a same-repository branch. See [GitHub's OIDC permissions reference](https://docs.github.com/en/actions/reference/security/oidc).

Authentication: OpenMetadata 2.0.7 rejects `AUTHENTICATION_PROVIDER=no-auth` (run 44765152599). The ephemeral stack uses the built-in `basic` provider, the default authorizer and JWT filter. The workflow logs in as the throwaway default admin, reads the default ingestion-bot JWT, masks both with `::add-mask::`, and renders the two ingestion configs (placeholder `__OM_JWT_TOKEN__`) into `RUNNER_TEMP`, which is deleted at the end of the job.
